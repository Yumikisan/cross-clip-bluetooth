# 文案规范（双端共用）

Applies to every user-visible string on both ends: settings, dialogs, toasts, notifications,
status bar, help, and error messages. The goal is that the same thing is called the same thing
everywhere, in both languages, and that no one has to read a paragraph to learn what a switch does.

## 一、术语表（唯一正确说法）

| 概念 | 中文 | 英文 | 禁止说法 |
|---|---|---|---|
| 产品 | Cross Clip | Cross Clip | CCB、ClipSync、本软件 |
| 指代自身 | 本应用 | the app | 本软件、本程序 |
| 连接 | 连接 | connection | 链路（技术文档可用，界面不用） |
| 配对 | 配对 | pair | 绑定 |
| 剪贴板 | 剪贴板 | clipboard | 剪切板 |
| 密钥（用户输入的那串） | 密钥 | key | 口令、密码、passphrase |
| 传输 | 传输 | transfer | 传送 |
| 大小上限 | 大小上限 | size limit | 文件限制、阈值 |
| 后台读取 | 后台读取 | background read | 后台监听、后台抓取 |
| 特权通道 | 后台读取通道 | privileged channel | 特权模式、增强模式 |
| 历史条目 | 条目 | entry | 记录项、卡片（指类型时） |
| 接收目录 | 接收目录 | save folder | 缓存目录、下载目录 |

## 二、句式规则

1. **设置项标题 = 名词短语**，不带动词，不超过 8 个字：
   ✅「自动同步剪贴板」 ❌「让你自动同步剪贴板内容」
2. **说明文字 = 一句话讲清"做什么 + 代价"**，中文 ≤ 40 字，英文 ≤ 90 字符：
   ✅「不再按上限拦截传输。经典蓝牙吞吐有限，建议只在临时需要时开启。」
   ❌ 三句以上、带因果链、带背景故事 → 挪到帮助页 FAQ。
3. **提示消息 = 结果 + 可选的下一步**，不出现"操作失败"这种无信息量的收尾：
   ✅「文件超过大小上限（8 MB）」 ❌「操作失败」
4. **不用感叹号**，不用"请"堆砌（一句话最多一个"请"）。
5. **错误消息必须说清是谁的问题、能做什么**：
   ✅「电脑没有确认收到文件（传输超时）」 ❌「发送失败」
6. 中英文**结构一致**：中文两句，英文就两句；不要一边三行一边半句。

## 三、占位符规则（改文案最容易踩的坑）

| 端 | 语法 | 写法 | 注意 |
|---|---|---|---|
| 安卓 | `String.format` | `%1$s` / `%2$d` / `%s` / `%d` | Kotlin 字面量里 `$` 必须转义成 `\$`，否则编译报 `Unresolved reference 's'` |
| Windows | `string.Format` | `{0}` / `{1}` | 不需要转义 |

**两端绝不能混用。** 把 `{0}` 写进安卓文案会让界面原样显示 `{0}`（`String.format` 不认识它），
反之把 `%1$s` 写进 Windows 文案会显示 `%1$s`。

审脚本已校验：同一键的中英两条，占位符集合必须相同。

## 四、分组命名（设置页）

| 组 | 中文 | 英文 | 内容 |
|---|---|---|---|
| sync | 同步 | Sync | 自动同步、自动复制、剪贴板文件、截屏同步、后台读取方式 |
| transfer | 传输 | Transfer | 大小上限、自适应、忽略上限、历史条数/展示 |
| security | 安全 | Security | 确认码、二层加密、密钥、安全日志、自检 |
| appearance | 外观 | Appearance | 主题、字号、标识色、间距、缩略图、来源设备名 |
| storage | 储存 | Storage | 占用统计、保留期限、阈值清理、接收目录 |
| behaviour | 行为 | Behaviour | 托盘、开机启动、置顶、快捷键、通知页面 |
| support | 帮助与反馈 | Help & feedback | FAQ、反馈、日志导出、入口链接 |
| about | 关于 | About | 版本、开发者链接 |

现有实现的分组顺序与上述不完全一致（历史原因），**但组名必须照此表**。

## 五、长度基线

| 位置 | 中文上限 | 英文上限 |
|---|---|---|
| 设置项标题 | 8 字 | 32 字符 |
| 设置项说明 | 40 字 | 90 字符 |
| Toast / 状态栏 | 16 字 | 48 字符 |
| 对话框正文 | 60 字 | 140 字符 |
| FAQ 单条答案 | 80 字 | 180 字符 |

超限就精简，不要缩字号，也不要把说明折成三行——那会让卡片高度失控。

## 六、审计方法

每次改完文案跑一次（脚本在会话里，可按需重建）：

1. 键齐平：安卓 `EN_MAP` 与 `ZH_MAP` 键集合必须完全相等；
2. 无缺失：代码里 `t("key")` / `Path=[key]` / `Loc.T("key")` 引用的键都必须在表里；
3. 无半翻译：Windows 表里每条 `Zh` 非空；
4. 无重复键：Windows 的 `Dictionary` 索引用 `["k"] = v` 初始化，**重复时会静默覆盖**（不抛异常），
   所以只能靠脚本查；
5. 占位符一致：同一键中英两版的占位符集合相同。

## 七、已修过的历史问题（别再犯）

- 安卓 `EN_MAP` 里混进中文（`dev_state_secure` / `dev_state_plain`），英文界面显示中文；
- Windows `lbl.about` 被定义两次：一次是"关于"标题位的简介，一次是旧面板的说明，后者覆盖前者，
  分组标题显示成了"仅使用蓝牙…"；已拆成 `lbl.aboutTitle` + `about.blurb`；
- Windows `kind.image/video/audio/archive` 同时存在单数与复数版本（条目标签 vs 存储统计），
  互相覆盖导致英文出现「Delete all Image」；已把单数版拆到 `kind.*.one`；
- 安卓长说明被截断显示（`+` 拼接的多行字符串在 UI 上只显示前半句），已压缩成一句话。
