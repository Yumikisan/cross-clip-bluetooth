# Cross Clip Bluetooth — 2.6.0 (Windows 2.5.0)

本版起使用独立的 `applicationId`，便于和官方 ClipSync 区分，两者可以**同时安装、同时使用**。

| 平台 | 文件 | 版本 |
| --- | --- | --- |
| Android 7.0+ | `CCB-Android-2.6.0.apk` | `versionCode 92` / `2.6.0`，`com.yumikisan.crossclip` |
| Windows 10/11 | `CCB-Windows-2.5.0.exe` | 自包含单文件，无需 .NET 运行时 |

## 改了什么

### 1. 安卓：独立 `applicationId`

`com.aubynsamuel.clipsync` → **`com.yumikisan.crossclip`**。

Kotlin 包名与 `namespace` 保持不变——它只负责类命名，与安装标识无关。

### 2. Windows：独立配置目录，且自动迁移

`%APPDATA%\ClipSync` → **`%APPDATA%\CrossClip`**。

首次启动时如果新目录不存在、旧目录存在，会自动复制一份过去——口令、历史、设置全部保留，不用重新配对。旧目录原样留着，官方版继续用自己的，两边互不干扰。

另外两项也一并改名，否则两个应用会互相抢：

- 单实例互斥名 → `Local\CrossClip.SingleInstance`
- 开机启动项注册表值名 → `Cross Clip`（旧的 `ClipSync` 在首次切换时被接管并删除）

### 3. 蓝牙协议未做改动

传输协议保持一致，仍可与官方 ClipSync 互传剪贴板与文件。

## 升级注意

- **安卓**：换了 `applicationId` 就读不到旧包的私有存储（`Android/data/<包名>/files`），因此会以全新档案启动，口令需要重新配一次。旧的 2.5.x 可以留着并存，也可以卸载。
- **Windows**：自动迁移，无需重配。
- **两个应用同时运行时**，只有一个能占用蓝牙 RFCOMM 监听，建议同一时间只开一个。

完整改动见 [CHANGELOG](https://github.com/Yumikisan/cross-clip-bluetooth/blob/main/CHANGELOG.md)。
